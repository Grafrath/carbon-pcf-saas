# Carbon-PCF SaaS

기업의 활동 데이터를 기반으로 탄소 배출량을 자동 계산하고 시각화하는 B2B 탄소 발자국 관리 대시보드입니다.

## 1. 프로젝트 개요 (Overview)

본 프로젝트는 기업이 배출하는 온실가스를 체계적으로 관리할 수 있도록 돕는 솔루션입니다.
엑셀 형태의 원시 활동 데이터를 업로드하면 시스템이 자동으로 표준 배출계수와 매칭하여 탄소 배출량(kg, t)을 계산하고,
이를 직관적인 대시보드(차트, 요약 카드, 상세 데이터 테이블)로 시각화합니다.

### ✦ 주요 기능

- **데이터 자동화:** 엑셀 파싱 및 DB 자동 임포트 (한전, 원소재, 운송 등 다양한 포맷 지원)
- **실시간 탄소 계산:** 활동량 × 배출계수 기반 정확한 탄소 배출량(kg, t 단위) 도출
- **직관적 지표 제공:** 배출량을 소나무 식재 효과 및 승용차 주행거리로 환산하여 제공
- **데이터 시각화 및 관리:** 카테고리별 배출량 차트 분석, 상세 내역 필터링 및 영구 삭제 기능
- **리포트 추출:** 필터링 및 가공된 데이터를 다시 엑셀 리포트 형태로 다운로드 (Export)

### ✦ 기술 스택 (Tech Stack)

- **Frontend:** Next.js (App Router), TypeScript, Tailwind CSS, lucide-react
- **Backend:** Next.js Route Handlers (API), Prisma ORM
- **Database:** PostgreSQL
- **Utilities:** xlsx (Excel Parsing)

## 2. 시스템 설계 이유 (System Architecture & Rationale)

**비즈니스 로직과 UI의 철저한 분리**
프론트엔드 코드의 복잡성을 낮추고 유지보수성을 극대화하기 위해 관심사 분리(Separation of Concerns) 원칙을 적용했습니다.
- **코어 로직 캡슐화:** 탄소 배출량 및 환산 지표를 계산하는 로직은 `utils/carbonCalculator`로 완전히 분리하여 단위 테스트 및 로직 재사용이 가능하도록 구성했습니다.
- **상태 관리 추상화:** 컴포넌트 내부에 복잡하게 얽힐 수 있는 상태 변수와 API 호출(Fetch, Delete) 로직을 `hooks/useActivities`라는 커스텀 훅으로 묶어, UI 컴포넌트는 오직 '화면을 그리는 역할'에만 집중하도록 설계했습니다.

**컴포넌트 모듈화 (Component Modularity)**
대시보드를 구성하는 요소들을 `ExcelUploader`, `ExcelDownloader`, `ActivityTable`, `EmissionChart` 등 독립적인 단위 컴포넌트로 세분화했습니다.
이를 통해 특정 기능 수정 시 타 로직을 건드리지 않고 안전하게 수정할 수 있으며, 코드의 가독성을 크게 높였습니다.

## 3. Trade-off 및 의사결정 경험

**① 엑셀 파싱 위치 결정: Client-side vs Server-side**
- **결정:** 엑셀 파일(`xlsx`) 파싱을 서버가 아닌 **클라이언트(브라우저)**에서 수행하도록 설계했습니다.
- **이유:** B2B 환경에서는 수천 건의 데이터가 담긴 무거운 엑셀 파일이 업로드될 수 있습니다. 이를 그대로 서버로 전송하면 대역폭 낭비 및 서버 메모리 부하가 발생합니다. 브라우저에서 먼저 파싱하여 필요한 JSON 데이터만 정제한 뒤 API로 전송함으로써 네트워크 비용을 절감하고, 오류 발생 시 사용자에게 즉각적인 UI 피드백을 제공할 수 있었습니다.

**② 데이터 검증 정책: 부분 성공 허용 vs 강한 정합성 (Rollback)**
- **결정:** 엑셀 데이터 임포트 시, 단 하나의 행이라도 배출계수 매칭에 실패하거나 형식이 어긋나면 **전체 트랜잭션을 취소(Rollback)**하는 강한 무결성 정책을 채택했습니다.
- **이유:** 탄소 배출량 데이터는 추후 외부 기관의 감사나 지속가능경영보고서(ESG)의 핵심 지표로 사용되므로, '일부만 저장된 불완전한 상태'를 방치하는 것은 치명적입니다. 엄격한 에러 처리를 통해 DB 데이터의 100% 신뢰성을 보장하고자 했습니다.

## 4. Scope 분류 기준 (GHG Protocol 기준)

본 서비스의 대시보드 및 DB는 글로벌 온실가스 회계 기준인 GHG Protocol에 입각하여 과제용 엑셀 데이터를 다음과 같이 분류하여 처리합니다.

- **Scope 2 (간접 배출):** 기업이 외부에서 구매하여 소비한 에너지. 본 프로젝트의 **[전기]** 카테고리(예: 한국전력 사용량)가 이에 해당합니다.
- **Scope 3 (기타 간접 배출):** 기업의 가치사슬(Value Chain) 전반에서 발생하는 모든 간접 배출. 본 프로젝트의 **[원소재]**, **[운송]** 카테고리가 해당되며, 제품 생산을 위한 원료 구매 및 물류 이동 시 발생하는 탄소를 추적합니다.
- *(참고: 제공된 과제 데이터셋의 특성을 반영하여, 사내 직접 연소 설비나 법인 차량 연료 사용 등 Scope 1에 해당하는 항목은 본 시스템의 측정 범위에서 제외/생략되었습니다.)*

## 5. AI 활용 범위 (Scope of AI Utilization)

본 프로젝트는 단순한 코드 작성을 넘어, 생산성 향상과 아키텍처 설계를 위한 **'페어 프로그래밍 파트너'**로서 AI Assistant를 적극적으로 활용했습니다.

1. **트러블슈팅 및 디버깅:** Next.js 15 버전 이상의 환경에서 발생하는 동적 라우팅 `params`의 비동기(Promise) 처리 에러 등 프레임워크의 최신 변경 사항으로 인한 이슈를 신속하게 추적하고 해결했습니다.
2. **로직 고도화:** 소나무 식재량, 승용차 주행거리 등 복잡한 비즈니스 계산 공식을 효율적인 유틸리티 함수로 변환하는 과정에서 AI의 검증을 거쳐 로직의 정확도를 높였습니다.

# 2. Docker Compose 빌드 및 백그라운드 실행
